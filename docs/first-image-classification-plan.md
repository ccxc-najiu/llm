# 网络编程的首轮图像分类实验方案

日期：2026-10-13。状态：待实施方案。当前仅保存方案，不开始实现、下载数据或训练。

## 实验目标

用少量基础结构写出一个图像分类程序，检验能否明确说明每个构造的计算含义，以及组合后哪些性质可以推导。

本方案承接 [网络编程语言的概念与设计设想](neural-programming-concept.md)。图像分类是第一个具体问题，重点是探索稳定、可复用的功能抽象及其组合方式。分类准确率是证据之一，不能单独证明网络编程的抽象已经成立。

首轮需要区分两类结果：由程序构造直接确定的结构性质，以及只有经过训练和测试才能确认的能力表现。

## 任务与数据范围

首轮建议使用合成图像，区分横向条纹和纵向条纹。逐渐改变位置、亮度、宽度和噪声，建立明确的适用范围与边界条件。

这个任务的类别定义与数据生成因素可控，有助于解释为什么某个程序可能识别方向，并预测它会在哪些变化下失效。具体图像尺寸、生成参数范围、样本量和训练预算，在实施前确定。

扩展顺序建议为：

1. 合成方向识别任务，检验基础抽象与组合规则。
2. Fashion-MNIST 等小规模真实图像分类，检验表达方式能否扩展。
3. ImageNet 作为后续应用与规模扩展场景。

这些是方案中的阶段建议，不表示已经完成数据准备或确定后续训练任务。

## 基础构造与组合规则

首轮只定义五种计算操作：

| 基础构造 | 精确计算含义 | 不由构造名称直接保证的功能 |
|---|---|---|
| 局部线性变换 | 对指定邻域加权求和，可共享参数 | 不自动等于边缘或纹理提取 |
| 逐点非线性 | 对每个数值应用明确函数 | 不自动等于概念激活 |
| 空间聚合 | 对指定区域求和、均值或最大值 | 不自动保证位置不变性 |
| 重排 | 改变维度组织，保留元素 | 不宣称产生新信息 |
| 全连接变换 | 对整个输入向量执行仿射变换 | 不自动具有分类器的任务含义 |

组合规则先支持串联、并联与合并。循环、持久状态、注意力和更复杂结构留到后续讨论。

每个构造都需要说明输入输出、计算公式、参数归属、信息访问范围及能够直接保证的性质。还需明确边界处理、元素顺序与合并方式，避免依靠隐含约定组合模块。

## 参数使用方式与拟议程序

参数的使用方式属于程序定义的一部分：

- **固定实例**：结构与参数都确定，直接引用。
- **可训练实例**：结构确定，参数通过训练选择。
- **共享实例**：多次调用使用同一份参数，而不是各自独立初始化的副本。

下面是拟议语法，用于表达设计意图，尚非可运行接口：

```python
responses = parallel(
    fixed(local_filter(horizontal_kernel)),
    fixed(local_filter(vertical_kernel)),
)

features = chain(
    responses,
    rectify(),
    spatial_mean(),
)

classifier = chain(
    features,
    learn(affine(outputs=2)),
)
```

“横向响应”和“纵向响应”需要由具体滤波器定义及测试支撑，不能仅凭变量名成立。`parallel` 的输出组织方式、聚合轴、滤波器方向约定与输出类别顺序需要显式规定。最终两个输出与标签的对应，由任务接口确定。

此程序旨在同时表达计算结构、已知部分与待学习部分。

## 三个对照版本

在同一任务与一致的数据划分上比较三个版本：

| 版本 | 构造方式 | 研究问题 |
|---|---|---|
| A | 固定特征计算与固定判断规则 | 能否完整解释并验证一个网络程序？ |
| B | 固定特征计算，只训练判断模块 | 能否保持中间含义，同时学习新的组合？ |
| C | 特征计算与判断模块联合训练 | 性能改变时，中间接口的含义是否仍然成立？ |

A 提供可理解的参照，B 检验模块组合，C 研究学习自由度与语义稳定性的冲突。三个版本不要求内部表示完全相同。

A 的适用范围和判定规则需要明确；固定参数不会自动带来正确性保证。B 与 C 的训练设置、冻结范围及参数共享关系需要记录，避免把配置差异误解为抽象本身的效果。

## 结构说明与能力验证

每个程序分别维护两份说明：

**结构说明**记录输入输出维度、局部连接、参数共享、聚合范围等可从定义检查的性质。

**能力证据**记录分类表现，以及位置、亮度、宽度、噪声和未见因素组合下的表现。这些结论来自实验，不作为结构天然保证的性质。

测试需要同时关注最终结果与中间接口。例如，一个通道若被称为“横向响应”，应检查训练前后它是否仍按约定响应横向结构。最终准确率提高，不代表中间语义得到保留。

实施时应明确训练、验证与最终测试的划分，记录随机种子和数据生成配置；诊断测试与适用范围也应提前定义。测试通过仅支撑所覆盖的条件，不宣称对任意图像成立。

## 交付内容与判断标准

首轮交付控制在四项：

1. 基础构造与组合规则规范。
2. 使用相同任务接口的三个网络程序。
3. 可控图像数据生成方式及诊断测试。
4. 结果分析，区分可由构造推导的性质与只能通过实验确认的行为。

成功标志是找到至少一种有明确适用范围、能够复用的功能抽象，并用它解释或预测组合行为。若只换了一种写法搭出分类网络，即使准确率很高，也尚未验证本设想的核心价值。

如果实验发现模块含义在训练中不稳定，或已有说明不足以推断组合结果，也应如实记录为对抽象设计的反馈，而不是仅通过扩大网络追求更高分数。
